# GitHub 主页维护流程

README 是默认分支上的手动维护文档，发布 APK 不会自动更新它。

每次发布应通过文档 PR 同步以下内容：

1. 以实际公开 Release、附件名与元数据核对版本、日期、包名、签名、大小及下载链接。
2. 更新顶部版本、下载按钮、本版新增、功能表及安装步骤，移除过时的“尚未发布”表述。
3. 把已实现、已验证、尚待验收和未来计划分开，保留已知问题与数据删除/迁移说明。
4. 更新变更历史；不修改旧标签和旧附件以伪装为新构建。
5. 如果源码尚在开发分支，用发布标签链接到对应指南、源码和协议，防止默认分支出现不存在的相对路径。
6. 检查所有站内链接和附件存在、Markdown目录及渲染，然后审阅PR差异并合入默认分支，回读远端README确认生效。

文档 PR 可以独立更新主页，不需要把未验收代码一并合入，也不触发新版本发布授权。
若维护仍采用“main保留基线”的方式，README必须明确源码状态；以后若改为main承载已验收代码，单独规划合并与回归。

新功能计划维护在 [NEXT_UPDATE.md](NEXT_UPDATE.md)，确认并实现后才写入已完成功能。
发布日期统一使用北京时间；大小明确区分下载/安装存储与运行RAM。
