# 独立动作包与安装管理（开发分支，未发布）

默认APK仅包含11段核心动画。95段扩展动画各自生成一个`.petanim`文件，用户按需导入。
本轮沿用无损透明WebP帧，不改变压缩格式。全部扩展动作都安装时，总素材占用仍接近旧完整包。

## 用户操作

1. 从首页“动画管理”或桌宠“动作选择 → 导入新动画”进入。
2. 先停止悬浮桌宠，再点击“导入新动画”，从手机文件中选择一个`.petanim`文件。
3. 校验成功后显示动作名称、素材版本和占用空间。
4. 回到首页启动桌宠，在“动作选择 → 已安装的扩展动作”中播放。
5. 删除扩展动作前同样先停止桌宠；确认删除后释放私有目录空间，不删除原始下载文件。

核心动画不可删除。重复动作不会重复安装；更换版本需先删除旧动作再导入。
格式或文件损坏会明确提示；失败导入不会加入动作列表。损坏的已安装动作显示为损坏，可删除重装。
不需要广泛文件访问权限，文件选择使用Android SAF。没有在线素材商店、自动下载或外置插件执行。
应用升级（同包名和签名）保留私有素材目录；清除应用数据或卸载会删除已安装素材。

## 制作现有95个动作包

在项目根目录使用构建虚拟环境的Python：

```sh
python scripts/export_android_assets.py --max-batch 3 --output dist/pack-source
python scripts/build_animation_packs.py --assets dist/pack-source --output dist/animation-packs
```

第一步准备完整素材但不会改变默认APK。第二步生成95个独立包和`index.json`（名称、版本、大小及完整ZIP SHA256）。
开发产物、帧缓存和素材包不提交Git。制作完成后可清理`dist/pack-source`，避免开发机保留重复帧。
本轮实际单包产物在云工作区`/workspace/deliverables/animation-packs/packs/`，尚未上传GitHub。

## 协议v1

`.petanim`是ZIP容器，只允许以下文件，不含目录条目、不含可执行代码：

- `pack.json`
- `NOTICE.txt`
- `THIRD_PARTY_NOTICES.md`
- `frames/f_0001.webp` 到 `frames/f_NNNN.webp`，每帧一张静态WebP

`pack.json`示意（hashes实际必须填写每个帧文件的64位十六进制SHA256）：

```json
{
  "schema": 1,
  "format": "webp-frames-v1",
  "character": "shenshen",
  "id": "ext_0123456789abcdef01234567",
  "version": 1,
  "name": "自定义动作",
  "nameEn": "Custom action",
  "canvas": [640, 360],
  "body": [212, 60, 428, 330],
  "fps": 24,
  "frames": 1,
  "crop": [0, 0, 640, 360],
  "noMirror": false,
  "hashes": ["填写第一帧的SHA256"]
}
```

目前只支持同一角色、640×360画布和相同身体锚点，不直接导入任意视频、GIF或新角色。
`id`为`ext_`加24位小写十六进制；现有动作包按源相对路径SHA256前24位生成，名称变化不会影响目录安全。
`version`是素材版本；`schema`和`format`决定协议兼容性，未来格式变化必须明确升级协议。
`noMirror`保护带文字动作，避免朝右时字迹反转。所有动作都作为手动动作播放，不接入余额或自动节日事件。
哈希用于完整性校验，不等同于作者签名或来源认证。

## 文件和运行边界

- 压缩输入最多300 MiB；实际解包最多256 MiB；单文件最多2 MiB；清单最多256 KiB。
- 每包1–1800帧，1–60fps；帧必须可解码为640×360静态WebP。
- 拒绝重复文件名、缺失/多余帧、目录条目、绝对路径、路径穿越、未知文件及不支持的协议。
- 每帧校验SHA256并解码验证，全部通过后把临时目录原子重命名为正式安装目录。
- 生命周期取消在读块和帧之间检查，失败清理临时目录；进程中断后下一次导入回收遗留临时目录。
- 悬浮服务持有素材使用租约。服务运行时拒绝安装和删除；写入时拒绝启动素材读取，避免播放器和管理器争抢文件。
- 停止服务时先关闭旧帧加载器，再释放租约。旧加载器的延迟回调不会影响新服务。
- 播放仍共用原有24 MiB帧缓存，不把所有已安装动作载入内存。
